# 2026-08-27 后续优化方向

按优先级排列，每项标注预估影响和实施成本。

## P0 — 立即可做（数据可靠性）

### 1. 数据迁移脚本
**问题**：当前重启应用 + schema 变更会清空 Milvus 向量数据，需要重新上传所有 PDF。
**方案**：
- 写一个 `MigrationService` 启动任务：检测 PostgreSQL 的 `policy_document` 表，对每个 status="现行/已废止" 的文档，如果 Milvus 里没有对应向量，重新调 DocumentService 的向量化流程
- 或保留旧 collection 的向量数据，用 `ALTER SCHEMA` 加 status 字段（Milvus 2.4+ 支持部分 schema 演进，需调研）
**影响**：避免每次重启丢数据
**成本**：中等，需写一致性校验逻辑

### 2. PDF 解析稳定性
**问题**：WPS 生成的 PDF 在 PDFBox 1.x 下触发大量 fontbox 报错，部分 PDF 提取出空文本。
**方案**：
- 升级 PDFBox 到 2.x 或 3.x（API 有差异，需调整 DocumentService）
- 或加 OCR 兜底（pytesseract + pdf2image）
- 或检测提取文本长度 < 50 时自动 OCR
**影响**：覆盖更多政策文档格式
**成本**：高，PDFBox 升级有 API 改动

## P1 — 体验优化（短期 1-2 周）

### 3. 混合检索（BM25 + 向量）
**问题**：当前只用语义搜索，关键词精确匹配场景（如政策编号 "2025年第89号"）召回率低。
**方案**：
- 引入 Apache Lucene 或 OpenSearch 做 BM25 索引
- 检索时两路召回，RRF（Reciprocal Rank Fusion）合并排序
- 把 status 加权放在融合之后
**影响**：召回率明显提升，特别是含数字、编号的查询
**成本**：中，需要引入新依赖

### 4. 多轮对话上下文
**问题**：当前每次问答独立，无法处理"那它的废止时间呢？"这种追问。
**方案**：
- `QaHistory` 已存历史，调 LLM 前从 sessionId 拉最近 3-5 轮
- Prompt 里加 "对话历史" 段落
- LLM 根据历史理解指代
**影响**：体验大幅提升，更接近真实助手
**成本**：低，主要是改 RAGService 和 Prompt 模板

### 5. 引用内容片段精炼
**问题**：当前 reference.content 是 chunk 前 200 字符截断，可能截在关键条款中间。
**方案**：
- 检索阶段按"段落完整性"切分，不要在句子中间断
- 引用时找最相关的 1-2 句而不是前 200 字
- 或用 LLM 对 chunk 提取关键句
**影响**：用户看到的引用更精准
**成本**：中

## P2 — 性能优化（中期）

### 6. 缓存层
**问题**：相同问题每次都重新做 Embedding + Milvus 检索 + LLM 调用，浪费算力和时间。
**方案**：
- 用 Caffeine 做内存缓存，key = question hash
- TTL 5-10 分钟（策略可能更新）
- 命中率应该不低（用户经常问相似问题）
**影响**：响应时间从秒级降到毫秒级
**成本**：低

### 7. 批量 Embedding
**问题**：上传 PDF 时一片一片向量化，串行慢。
**方案**：
- MiniMax Embedding API 支持 batch（看文档），改 `embed()` 接受 `List<String>`
- 一次传 16-32 个 chunk，减少 HTTP 调用次数
**影响**：上传耗时减少 5-10x
**成本**：低

### 8. 异步处理上传
**问题**：上传大 PDF 同步等待解析 + 向量化 + 入库，HTTP 连接占用久。
**方案**：
- 上传接口立即返回 `document_id` + status="processing"
- 后台 `@Async` 任务做实际处理
- 前端轮询或 WebSocket 推送进度
**影响**：大文件上传体验好
**成本**：中，要加状态机和轮询接口

## P3 — 高级能力（长期）

### 9. 多模态文档支持
扫描件 PDF、图片需要 OCR；当前 PDFBox 只能提文本。
**方案**：集成 PaddleOCR 或商用 OCR API
**成本**：高

### 10. 政策时间线视图
按发布日期/废止日期组织政策，做成时间轴 UI。
**方案**：PostgreSQL 已有 publishDate/expireDate，加专门查询接口
**成本**：低-中

### 11. 答案可信度评估
LLM 可能胡说八道（幻觉），需要让模型在找不到时明确告知。
**方案**：
- 检查 retrieval 相似度，低于阈值直接返回"未找到相关政策"
- 让 LLM 在答案里引用具体公告编号，未引用的视为不可信
**成本**：中

### 12. A/B 测试框架
不同 Prompt、排序权重对答案质量的影响需要量化。
**方案**：
- 加 experiment_id 字段到 QaHistory
- 用户分层路由到不同配置
- 离线评估答案质量
**成本**：高
