# 2026-08-27 开发日志

## 今日目标
打通 CustomsWise RAG 系统的完整端到端流程：上传 PDF → 向量化入库 → 智能问答 → 排序返回。

## 完成情况

### ✅ 已修复的核心问题

#### 1. MiniMax Embedding API 调用
- **问题**：API 返回 `2013 missing required parameter` 错误
- **原因**：Embedding 接口要求 `type` 字段（`"db"` 用于入库 / `"query"` 用于查询）
- **修复**：`MiniMaxService.embed()` 请求体加上 `"type": "db"`
- **验证**：返回 200，向量维度 1536

#### 2. Milvus Collection schema 不完整
- **问题**：搜索返回 0 条结果（`Illegal field name: text`）
- **原因**：旧 schema 缺少 `text`、`document_id`、`status` 字段
- **修复**：`MilvusService.createCollection()` 重新声明完整 schema
  - `id` (Int64, 主键, 自增)
  - `vector` (FloatVector, 1536 维)
  - `text` (VarChar 65535) — 原始文本
  - `document_id` (VarChar 100) — 关联 PG 文档
  - `status` (VarChar 20) — **新增**，用于排序加权

#### 3. `@PostConstruct` 每次重启清空数据
- **问题**：重启应用后 Milvus collection 被重建，所有向量数据丢失
- **修复**：改成 schema 完整性检测
  - 存在 → 检查 `status` 字段是否齐全
  - 缺失 → 自动重建（一次性丢数据）
  - 齐全 → 保留数据 ✅
- **副作用**：用户每次重启需要重新上传 PDF

#### 4. searchVectors API 用法错误
- **问题 1**：`withOutputFields` 不存在
- **问题 2**：`SearchResultsWrapper.getResultCount/getText/getScore` 在 2.4.5 版本不存在
- **问题 3**：按 query 索引循环时跳号导致 `Illegal index of target: 1`
- **修复**：改用 `getFieldWrapper(name).getFieldData()` 拿全部结果，单独 `getIDScore(0)` 拿分数

#### 5. L2 距离排序语义错误
- **问题**：直接对 L2 距离乘 boost（L2 越大越不相似，加权后语义混乱）
- **修复**：先转相似度 `similarity = 1 / (1 + distance)`，再按 status 加权
  - 现行：`sim × 2.0`
  - 已废止：`sim × 0.3`

#### 6. MiniMax Chat 响应解析失败
- **问题**：原代码读 `choices[0].messages`，实际字段是 `choices[0].message.content`
- **修复**：兼容多种字段名（`message.content` → `messages` → `text`），并打印完整响应日志
