## 完成情况

### ✅ Milvus 优雅降级（无 Milvus 时项目可正常启动）

**背景**：之前 Milvus 连接失败（超时 10s）会阻断 Spring Boot 启动，本地没有 Milvus 时无法开发调试。

**改造**：三级降级：
1. `MilvusConfig`：连接超时从默认 10s → **2s**，失败返回 `null`
2. `MilvusService`：`@Autowired(required=false)` 允许 null 注入；`available` 字段追踪状态；所有 CRUD 方法前加空检查
3. `MilvusServiceV2`：委托 `MilvusService.isAvailable()`；各操作加空检查
4. `MigrationService`：启动对账前检查 Milvus 可用性，不可用直接跳过
5. `RAGService`：`ask()` 前检查 Milvus，可用时返回友好错误提示

**降级行为**：

| 场景 | 行为 |
|------|------|
| 无 Milvus 时启动 | Spring Boot **正常启动**，日志输出 `⚠️ Milvus 不可用` |
| 文档上传 | **正常**，PDF 解析/分块/写 PG 都不依赖 Milvus |
| RAG 问答 | 返回：`"向量数据库（Milvus）未连接，RAG 功能暂不可用"` |
| 启动对账 | 直接跳过，不报错 |
| Milvus 恢复后 | 需**重启**应用才能恢复 RAG 功能 |

### ✅ 接入本地 BGE-rerank-v2-m3（替代 MiniMax rerank）

**背景**：MiniMax 公开 API 无 rerank 端点，`rag.rerank.enabled=false` 相当于关闭层 3 重排。本地已部署 BGE-rerank-v2-m3（Python 服务，`http://127.0.0.1:8001/v1/rerank`）。

**改造**：`RerankService` 完全重写：
- 移除 `MiniMaxService` 依赖，改为直接调用本地 BGE rerank HTTP 接口
- 使用现有 `minimaxHttpClient` 共享连接池
- 超时 5s，失败自动降级回原始排序（日志 `[BGE_RERANK]`）
- `application.yml`：`rag.rerank.enabled=true`，新增 `url` 和 `timeout-ms`

**验证**：BGE 服务关闭后重试，确认降级、不报异常。

### ✅ 多模态 OCR（PaddleOcrExtractor）

**架构**：与 BGE rerank 完全一致——Python PaddleOCR HTTP 服务（本地端口），Java 通过 HTTP 调用，不引入重型 Java OCR 依赖。

**优先级链**（从小到大）：
```
PdfBoxExtractor(10) → PaddleOcrExtractor(15) → OcrExtractor(20, tess4j)
```

**新增文件**：`PaddleOcrExtractor.java`
- implements `PdfExtractor`，`priority()=15`
- 每页 PDF 渲染为 `BufferedImage`（复用 `OcrExtractor` 的 `PDFRenderer`），POST `/ocr` 传 base64 PNG
- 配置：`paddleocr.url`、`timeout-ms`、`dpi=250`、`connect-timeout-ms=3000`
- 失败 → `ExtractionResult.empty()` → 降级到 tess4j

**application.yml 配置**：
```yaml
paddleocr:
  enabled: true
  url: http://127.0.0.1:8002/ocr
  timeout-ms: 10000
  dpi: 250
  connect-timeout-ms: 3000
```

### ✅ 答案可信度评估（防 LLM 幻觉）

**背景**：LLM 可能胡编答案（幻觉），需要让用户知道答案的可信程度。

**评估方式**：
1. **topSimilarity**：rerank 后第一名 chunk 的相似度得分
2. **citationsPresent**：LLM 答案中是否包含参考文档的 `documentNumber`

**置信度公式**：
```
score = topSimilarityWeight(0.7) × topSim + citationWeight(0.3) × citedScore
citedScore = 1.0 if LLM cited at least one doc number, else 0.0
```

**等级映射**：

| Level | 触发条件 | 行为 |
|-------|---------|------|
| `high` | score ≥ 0.7 | 无额外提示 |
| `medium` | 0.4 ≤ score < 0.7 | 追加：`"以上回答基于检索到的政策资料，但相似度有限，仅供参考，不构成法律建议。"` |
| `low` | score < 0.4 | 追加：`"未检索到高度相关的政策资料，建议换个关键词重试。"` |

**新增字段**：
- `QaResponse`：新增 `confidenceScore`、`confidenceLevel`、`citationsPresent`
- `QaHistory`：新增对应三列

**新增服务**：`AnswerCredibilityService.java`
- `evaluate(topSimilarity, references, answer)` → `CredibilityResult(score, level, cited)`
- `disclaimer(level)` → 追加文本

### ✅ A/B 测试框架

**背景**：需要量化不同配置（阈值、Prompt）对答案质量的影响。

**方案**：SessionId 哈希取模做 sticky 分组（control 50% / treatment 50%），`QaHistory` 记录 `experimentId` 供离线分析。

**新增服务**：`ExperimentService.java`
```java
// 确定性分组：hash(sessionId + experimentId) % 100
String group = bucket < 50 ? "control" : "treatment";
```

**新增字段**：`QaHistory.experiment_id`

**配置**（默认关闭）：
```yaml
experiments:
  enabled: false
```
