### ✅ #2 BGE rerank fallback 指标告警

**背景**：昨天 RerankService 加固了抗超时逻辑（5s→30s / candidate-cap=4 / consume+toString bug 修复），但 fallback 路径只剩日志 `log.info/error` 单点暴露，运维侧无告警渠道。

**改造**：
- `pom.xml`：加 `spring-boot-starter-actuator` + `micrometer-registry-prometheus`（Spring Boot 官方 starter，无需额外版本）
- `application.yml`：新增 `management.*` 配置段，暴露 `health,info,prometheus` 端点，全局 tag `application=${spring.application.name}`，`http.server.requests` 开直方图
- `RerankService`：构造器注入 `MeterRegistry`，在两处 fallback 路径埋点：
  - `api_returned_null`（line 113）：scores 为 null/空
  - catch-all（line 134）：异常类名作为 reason

**指标**：
```
rag_rerank_fallback_total{application="customswise-rag", reason="<原因>"} <计数>
```

**告警规则**（Prometheus / AlertManager，建议配置）：
```yaml
- alert: RerankFallbackHigh
  expr: sum by (reason) (rate(rag_rerank_fallback_total[5m])) > 10/60
  for: 2m
  annotations:
    summary: "BGE rerank fallback 频率过高"
    description: "{{ $labels.reason }} 5min 内平均 {{ $value }} 次/秒"
```

### ✅ #3 references_info JSONB→TEXT 迁移脚本

**背景**：昨天 commit `3e2e089` 把 `qa_history.references_info` 从 JSONB 改为 TEXT，schema.sql / QaHistory.java 已对齐新类型，但 **存量数据库** 列还是 JSONB，Hibernate `ddl-auto:update` 不会主动 ALTER 跨类型列（特别是破坏性类型变更）。

**新增文件**：
- `src/main/resources/db/migration/V20260831__qa_history_references_info_jsonb_to_text.sql`
- `src/main/resources/db/migration/README.md`

**脚本要点**：
- 用 `DO $$ ... $$` 包一层 idempotent 检查，先查 `information_schema.columns` 确认当前类型是 JSONB
- 是 JSONB → `ALTER COLUMN ... TYPE TEXT USING references_info::text`（USING 子句对每行反序列化，零数据丢失）
- 不是 JSONB → NOOP + `RAISE NOTICE`，可重复执行不炸
- 脚本末尾附 3 条手动校验 SQL（类型确认 / 抽样 JSON 合法性 / 非空率），不直接执行

**README 要点**：
- 文件命名约定 `V<YYYYMMDD>__<scope>_<description>.sql`
- 适用场景：仅存量 DB（schema.sql 已对齐新类型，全新部署不需要）
- 运行方式：psql `--single-transaction` 干跑
- 新增脚本流程：注释背景 / 风险 / 锁表时长 / 校验 SQL / 在 README 登记

## 今日小问题

1. **告警规则需要部署 Prometheus + AlertManager 才生效**：仅加埋点不会自动告警，要看运维侧是否已配。短期待办是把上面那段告警规则贴到 `infra/prometheus/alerts.yml`（如果有的话）。
2. **迁移脚本是手动执行**：项目没有 Flyway/Liquibase，所以这次跑完后需要在 DBA runbook / wiki 登记；下次 schema 变更如果频繁，可以考虑引入 Flyway。
3. **`reason` tag cardinality**：catch-all 用 `e.getClass().getSimpleName()` 作为 reason，理论上有限类（IOException / ConnectException / SocketTimeoutException / RuntimeException 等），cardinality 风险低。如果未来出现自定义异常类型爆炸，再考虑改成 hash + bucket。
4. **actuator 暴露面**：当前开了 `health,info,prometheus`，未做权限控制；生产环境如果 actuator 端点对外开放，需要加 Spring Security 限定来源 IP 或 basic auth。
